# update-delivery-suggester

定例MTG後のアポ打診・新機能デリバリーを支援するAIスキル。
メディカルフォース（電子カルテ）のアップデート情報とSalesforceのMTGメモを照合し、
確定／候補／対象外の3段階で整理する。最終的なデリバリー文面まで出力する。

---

## 使い方

### インプットの準備

**① アップデート情報.md（準備不要）**
Project Knowledgeに格納済みの最新版を自動参照する。毎回アップロードする必要はない。
※正本はエンジニアが管理するGoogle Drive上の「アップデート情報.md」。Project Knowledgeへは
月次または新機能リリース時に、担当者が手動でダウンロード→再アップロードして同期している
（詳細は下記「運用ルール」参照）。

**② SalesforceのMTGメモ**
以下のフィールドが写っているスクショを撮る：
- 議事録サマリ（決定事項・ペンディング事項・ネクストアクション）
- 先方課題
- 持ち帰り事項

**③ Salesforceの契約状況（Claude Code環境でSOQLが叩ける場合のみ）**
MTGメモだけでは「導入検討中」と書かれていても、実はMTG後に受注済みで利用開始日待ちなだけ、
というケースがある。これを防ぐため、マッチング前に以下をSOQLで確認する。
- Account.`Function__c`（利用機能）：契約していない機能カテゴリ（保険・決済端末・広告効果測定・
  在庫管理など）のアップデートはそもそも対象外にする
- そのAccountに紐づくOpportunity履歴（`StageName`・`CloseDate`・`upsell_feature__c`・
  `Field21__c`＝変更適応日）：MTG後に受注した機能や、過去に失注した機能を把握する
- 注意：`Function__c`は受注時点で更新されるため、実際の利用開始日（`変更適応日`）とはズレることがある。
  「契約済み・利用開始待ち」と「現在運用中」は区別して案内する

claude.aiプロジェクト等、SOQLが叩けない環境ではこのステップは省略し、MTGメモのみで照合してよい
（詳細な運用はSKILL.mdの「契約状況の確認（スコープ確認）」を参照）。

### Claude Projectへの入力

1. `update-delivery-suggester` プロジェクトを開く
2. SFスクショを貼り付ける
3. 顧客名とSFのレコードURLを添えて送信する

例：
```
恵比寿ブライトスキンクリニック
SF：https://xxxxx

このデータからお願い
```

### 確認ステップ

AIから「確定・候補・対象外・汎用アップデート」の一覧が出たら、**すべてに目を通す**。
確定だから、候補だから、と一部だけ見て次に進まない。

- **確定** → そのまま扱ってよいか確認する（顧客文脈と食い違っていれば指摘する）
- **候補** → 件ごとに以下を返信する
  - 使える → 「確定に格上げ」
  - 案内済み → 「○番は案内済み」
  - 不要 → 「○番は対象外」
- **対象外** → 本来デリバリーすべきものが紛れていないか（見逃し）を確認する
- **汎用アップデート** → 課題ひも付けはないが、そのまま使えそうなものを確認する（不要なら省いてよい）

全件の確認が終わるまで、次のデリバリーパターンの選択には進まない。

### デリバリーパターンの選択

確認が終わったら、デリバリーパターンを選ぶ。

- **共有のみ** → 配信文面のみが出力される
- **アポ打診** → タイトル化メモ＋配信文面の2ブロックが出力される

## 運用ルール

| 項目 | 担当 | 備考 |
|---|---|---|
| スキルを実行する | 各CSメンバー | 担当している60社のリストを作り、月次で上から順に回す（会えない顧客にもアップデート接点を作るため） |
| 出力の最終確認 | 担当CS（自分） | 確定・候補・対象外、すべて毎回目視確認する。省略しない |
| CSメンバーへの展開判断 | プロジェクト作成者 | 3〜5社分を回し、確定・候補すべてがCSの目から見て妥当と判断できたら展開する |
| スキルの改善・更新 | （担当者名を記入・未定） | SKILL.mdを編集してGitHubにpush |
| アップデート情報.mdの正本管理 | エンジニア | Google Drive上のファイル。2022年〜の全アップデート履歴が1ファイルに蓄積されている |
| アップデート情報.mdの同期（Project Knowledgeへの反映） | 佐久間（プロジェクト作成者） | 月次または新機能リリース時。Google Driveの画面でファイルを選択し「ダウンロード」する（コピー&ペーストではなく、この方法でのみ全文が欠落なく取得できる。詳細は下記Phase参照）→Project Knowledge内の既存ファイルを削除してから同名で再アップロードする（重複ファイルを残さない） |
| 「案内済み」かどうかの判断 | — | 専用の管理ログは持たず、SalesforceのMTGメモの記載を信頼する |

## Phase／今後の展望

- **Phase1（現在の運用）**：本ドキュメントの内容。SalesforceのMTGメモはスクショで手動入力し、
  アップデート情報.mdはProject Knowledgeへの手動同期で運用する。
- **Phase2（技術検証済み・未着手）**：SalesforceのVideoCall／Onboarding__c／Accountオブジェクトから、
  SOQLでMTGメモ（決定事項・課題・持ち帰り事項）を自動取得できることを検証済み
  （565件のVideoCallデータ、248クライアント分を確認）。
  ただしclaude.aiにはSalesforceのネイティブコネクタが無いため、自動取得はClaude Code環境で行う想定。
  トークンコストと利用者ごとの温度差を踏まえ、スケジュール実行や共有書き出し先を用意する
  集中管理型のパイプラインは見送り、「使いたい人が使えるレシピ（Claude Code用の手順書）」として
  別途配布する方針（手順書自体は未作成）。使わない場合は引き続きPhase1のスクショ運用でよい。
- **契約状況の確認（2026年7月・実クライアント検証済み）**：大翔会 gift clinicの定例準備で、
  MTGメモ上は「導入検討中（ペンディング）」だった機能が、実はMTG後の商談で受注済み（Opportunityの
  `StageName`＝アップセル受注）だったケースを確認。Account.`Function__c`（利用機能）とOpportunity履歴
  （`upsell_feature__c`・`Field21__c`＝変更適応日）をあわせて見ることで、MTGメモだけでは分からない
  「受注済みだが未開始」の状態や、契約外カテゴリ（保険・決済端末・広告効果測定・在庫管理など）を
  正確に把握できることを確認した。クリニックごとの契約状況をスナップショットとしてファイル保存する案も
  出たが、現時点では都度SOQLで確認する運用とし、保存の仕組み化は見送っている。
- **アップデート情報.mdの取得方法（検証済み）**：エンジニアが管理するGoogle Drive上の
  「アップデート情報.md」は2022年から途切れず1ファイルに蓄積され続けている（2026年7月時点で約1.4MB）。
  AIツール（Claude Codeの読み込み・全文検索機能）経由で内容を取得しようとすると、ファイル末尾
  （＝一番知りたい直近の更新分）に技術的に到達できないことを確認した（2025年7月分までしか取得できず、
  2026年分が欠落する）。**一方、Google Driveのブラウザ画面でファイルを選択し「ダウンロード」する方法
  （コピー&ペーストではない）であれば、数クリックで元ファイルとバイト単位で完全一致するデータが
  取得できることを確認済み。** アップデート情報.mdに限らず、操作マニュアル.md／よくある質問.md／
  活用ヒント.md／操作マニュアル（保険）.mdも同じ方法で欠落なく取得できる。
  Claude Codeで使う場合は、これらをローカルの`manuals/`フォルダ（またはそれに準じる場所）に
  ダウンロードして置いておくと、MFの機能を正確に把握した上でマッチング判断ができる。
